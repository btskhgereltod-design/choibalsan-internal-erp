# OVERVA BA Knowledge Library

This library turns reviewed Business Analysis theory into governed analytical guidance for OVERVA. It is broader than organization structure: it supports process discovery, Smart Import, workflow design, module selection, management metrics, controlled change, and solution evaluation.

## Source boundary

The registered sources are BA Lessons 1, 2, 3, 4, 5, and 7 supplied for review. OVERVA retains only reusable principles and source traceability.

The following are deliberately excluded:

- course exercises and answer instructions;
- fictional organizations and sample project facts;
- example process, order, delivery, product, or customer data;
- any statement that has not been confirmed as evidence for the current tenant.

Uploaded material is never allowed to override system security, privacy, output schema, approval, or tenant-isolation rules.

## Governed topics

1. Ecosystem — right problem, right stakeholders, explicit roles, and value.
2. Needs assessment — current evidence, root cause, future outcome, gap, options, feasibility, and measurable success.
3. Planning — scope, stakeholder engagement, communication, analysis work, controlled change, and evaluation.
4. Elicitation — document analysis, interview, workshop, observation, survey, prototype, confirmation, and follow-up.
5. Process modeling — select the simplest model that answers the business question; separate As-Is and To-Be.
6. Requirements — keep finding, need, gap, requirement, and solution option separate; define acceptance and quality.
7. Traceability and monitoring — baseline, status, coverage, change impact, release, and measured outcome.

## Runtime contract

At runtime, OVERVA loads only knowledge units tied to the active method version and the current interview stage, plus cross-cutting safeguards. No more than eight units are sent for one normalization request. These units guide analysis; they are never treated as facts about the organization.

Tenant answers remain private, append-only evidence. A human confirms each normalized answer, approves structure and workflow proposals, and activates shared method versions from `admin.overva.com`.

## Learning boundary

`tenant evidence -> confirmed finding -> requirement/proposal -> human decision -> measured outcome -> anonymized candidate -> platform review -> new catalog or method version`

One organization's raw data never becomes another organization's truth.
